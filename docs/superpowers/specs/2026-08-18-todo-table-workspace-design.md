# Todo 表格式工作区设计

## 目标

将 Todo 页面从“顶部快捷输入 + 卡片式任务行”调整为以待办列表为主体的表格式工作区。桌面端强调稳定的列对齐和快速扫描，移动端保留紧凑、可操作的折叠布局；新建待办改由独立抽屉完成。

## 范围

- 仅修改 `apps/web`，不改变 API、任务模型、筛选、排序、cursor 分页或任务树业务规则。
- 保留上一轮已确认的 `1440px` 页面主体、`272px` 筛选栏、紧凑行距和加宽编辑抽屉。
- 保留左侧筛选、内联状态切换、任务编辑抽屉和父任务编辑抽屉内的子待办创建入口。
- 删除页面顶部的 `QuickCreateForm` 直接输入区域。
- 在列表工具栏增加“新建待办”按钮，打开响应式新建抽屉。

## 页面层级

桌面端结构：

```text
┌──────────────────────────────────────────────────────────────────┐
│ Tickly / 账号信息                                                │
├───────────────┬──────────────────────────────────────────────────┤
│ 筛选          │ Todo list                         [+ 新建待办]  │
│               │ 当前筛选：进行中 · Tickly                       │
│               │                                                  │
│               │  #   待办          主题   优先级  截止   状态   │
│               │ ──────────────────────────────────────────────── │
│               │ 42   完成表格化  Tickly  中      08-20  ...    │
│               │      └ 移动适配  Tickly  低      —      ...    │
└───────────────┴──────────────────────────────────────────────────┘
```

- 移除“今天要完成什么？”大标题，减少列表上方占用。
- 工具栏只承载列表名称、新建按钮和已有的当前筛选摘要。
- 不显示任务总数：当前 API 只有 cursor 分页，没有可靠总数，避免把已加载数量误称为总量。
- 表头是辅助列标尺：小号浅色文字、透明背景和单条细分隔线，不使用单元格边框。
- 正文通过列对齐、留白、分组分隔线和轻微 hover 表达结构。

## 表格结构

桌面端使用语义化 `<table>`，包含以下六列：

1. `#`：账号内任务编号。
2. `待办`：标题、父任务进度、上下文提示和子待办缩进。
3. `主题`。
4. `优先级`。
5. `截止时间`。
6. `状态`：保留现有内联下拉切换。

任务标题列占据剩余主要宽度；其他列使用稳定宽度。创建时间、完成时间和完整描述继续在编辑抽屉展示，不挤占主列表。

每个根 `TaskGroup` 对应一个 `<tbody>`：

- 根任务是第一行。
- 子待办是随后缩进的行，保持现有一层父子关系。
- 父任务有子待办时，在待办列显示 `已完成数/总数`。
- `context_only` 根任务继续显示“仅用于展示匹配的子待办”，但提示收进待办单元格。
- 点击待办单元格中的按钮打开现有编辑抽屉；状态下拉只执行状态切换，不触发编辑。

加载、空数据、首屏错误、增量错误和“加载更多”保持现有状态语义。无数据时使用跨六列状态行；增量错误和分页入口放在表格下方，不改变请求逻辑。

## 移动端

- 使用同一份表格 DOM，不重复渲染按钮或表单。
- 表头在视觉上隐藏但继续保留给辅助技术。
- 每个任务行折叠为紧凑网格：编号、标题和状态为第一层；主题、优先级和截止时间为第二层。
- 子待办继续通过缩进和细引导线表达层级。
- 新建与编辑面板沿用现有响应式模式，在移动端呈现为底部全宽面板。

## 新建待办抽屉

新增独立 `TaskCreatePanel`，不把创建与现有大型编辑组件强行抽象为通用表单。

入口与字段：

- 工具栏“新建待办”按钮打开右侧抽屉。
- 标题：必填，最大 200 字符。
- 描述：可选，最大 4000 字符；空值不发送，由当前 API 以标题作为描述。
- 主题：必填，最大 100 字符，提供已有主题 datalist。
- 优先级：可选。
- 截止时间：可选，按账号时区输入并在提交边界转换为 UTC。
- 不显示状态字段，新任务沿用服务端默认 `new`。
- 不显示父任务字段，工具栏入口只创建顶层待办；子待办继续从父任务编辑抽屉创建。

当前主题筛选只在抽屉打开时用于预填主题，用户可覆盖。关闭包含未提交输入的抽屉前显示放弃确认。

提交行为：

- 前端先规范化标题、描述和主题；标题或主题为空时显示字段错误，不发请求。
- 提交期间禁用表单、关闭和重复提交。
- 创建失败时保留所有输入，并在抽屉内显示安全错误信息。
- 创建成功后清空并关闭抽屉，沿用 `useTaskWorkspace.actions.create` 的列表刷新、结构变更互斥和主题刷新行为。
- 当前筛选不匹配新任务时保持筛选不变，不为了显示新任务而隐式重置查询。

  - 增加新建抽屉打开状态、脏状态和错误协调。

- 新增 `task-create-panel.tsx`

  - 在引用和测试迁移完成后删除。

不新增依赖，不创建共享 workspace 包，不改动 API。

## 可访问性与状态

- 表格提供可读 caption；弱化表头不等于删除列语义。
- 新建抽屉使用 Base UI Dialog 的标题、描述、焦点约束和 Escape 行为。
- 脏表单关闭确认同时覆盖关闭按钮、Backdrop 和 Escape。
- 创建中通过可见按钮文本和 `aria-live` 状态告知进度。
- 状态下拉保持独立可访问名称；任务标题按钮保持明确的“编辑”名称。
- 保留错误、空状态、加载中和分页的可读状态提示。

## 测试与验证

新增或更新 Web 测试，覆盖：

- 顶部快捷新增区域消失，新建按钮打开抽屉。
- 主题筛选在打开时预填且可被用户覆盖。
- 必填校验、描述省略、优先级和截止时间生成正确 `TaskCreateInput`。
- 创建中防重复提交；失败保留输入；成功关闭抽屉并刷新列表。
- 脏表单关闭确认与焦点约束。
- 六列表头、父子任务行、父任务进度、上下文提示和状态切换。
- 加载、空数据、错误和 cursor 分页状态保持有效。
- 既有任务编辑、删除、子待办创建和筛选测试继续通过。
- 排版契约测试更新为新的表格和抽屉规则，并避免测试字符串产生无用 Tailwind utility。
